# Generated data

Files here are generated by `notebooks/01_eda.ipynb`. Do not edit them by hand; re-run the EDA notebook instead.

## Output file

`bpic15_events.csv.gz`: the event log as one table, saved by section 12 of `notebooks/01_eda.ipynb` from
`data/raw/BPIC15_1.xes` (read with PM4Py, saved with pandas as a gzip-compressed CSV).

- 52,217 rows (one per recorded event), 1,199 cases, all 29 original columns with their original names and order.
- No rows are removed, no values are filled and no values are changed; a check in the notebook confirms that the reloaded
  file is identical to the original table.
- The rows keep the original order (sorted by case, and within a case in the order of the original file). This matters
  because many events share the same timestamp.
- Identifiers are kept as text: case IDs (`case:concept:name`) and resource IDs (`org:resource`, `monitoringResource`,
  `case:Responsible_actor`). Resource IDs are numbers, not names.
- `notebooks/02_modelling.ipynb` loads this file (section 3) and never reads the raw XES file.

## Mini data dictionary

The columns used by the models are described here; all 29 columns are described in
[`../data_dictionary.csv`](../data_dictionary.csv).

| Output file | Column | Meaning | Units / values |
|---|---|---|---|
| `bpic15_events.csv.gz` | `case:concept:name` | Case ID (one building-permit application) | Text; 1,199 values |
| `bpic15_events.csv.gz` | `concept:name` | Activity code of the event | Text code such as `01_HOOFD_010`; 398 codes |
| `bpic15_events.csv.gz` | `activityNameEN` | English description of the activity | Text; 289 descriptions |
| `bpic15_events.csv.gz` | `time:timestamp` | When the event was recorded | Date and time in **UTC**, microsecond precision; 45.9% are at exactly local midnight (probably a date only) |
| `bpic15_events.csv.gz` | `org:resource` | Resource ID linked to the event | Text (number); 23 values |
| `bpic15_events.csv.gz` | `case:endDate` | Recorded end date of the case (meaning not fully documented) | Date and time in UTC; empty for 243 cases |
| `bpic15_events.csv.gz` | `case:SUMleges` | Fee of the application | Number (currency not stated); empty when missing |

## How to load it

Read every column as text, so nothing is changed by automatic type guessing; only empty cells become missing values (the
text `EMPTY` in `question` is a real value). Then turn the six date columns (`time:timestamp`, `case:endDate`,
`case:startDate`, `case:endDatePlanned`, `dueDate`, `planned`) back into UTC dates with microsecond precision, and
`case:SUMleges` into a number. The exact code is in section 12 of `notebooks/01_eda.ipynb` and section 3 of
`notebooks/02_modelling.ipynb`.
